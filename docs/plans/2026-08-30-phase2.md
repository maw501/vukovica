# Vukovica Phase 2 Implementation Plan — Progression + Reader

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the MVP toolbox into a staged learning path (Азбука → Речи → Читање → Разговор) and add the graded reader for children's-book-style stories.

**Architecture:** Pure stage logic in `lib/stages.ts` fed by one batched `api.getProgress()`; dashboard restructured around the current stage; new `stories` table + `story` Edge Function (Sonnet-tier via `vuk('chat')`) that generates AND inserts; reader screens with tap-word glosses (card match → AI gloss fallback → key-missing degrade). Chat demoted, untouched otherwise.

**Tech Stack:** unchanged (Expo SDK 54, supabase-js under RLS, Deno Edge Functions + Vercel AI SDK, vitest).

**Spec:** `docs/specs/2026-08-30-phase2-progression-reader.md` — READ FIRST. MVP conventions (grants, RPC patterns, prompt discipline, verification style) carry over from `docs/specs/2026-08-29-vukovica-design.md` and the codebase.

## Global Constraints

- Branch `mvp`, building on HEAD (23b2a03+). `npm test` + `npm run typecheck` green at every task end; commit per task (conventional commits).
- Stages are SOFT: emphasis/goals only, never gate a screen.
- Mastery rule verbatim: letter mastered ⇔ lifetime attempts ≥ 8 AND correct/attempts ≥ 0.9; 30 letters total. Known word ⇔ `user_cards.state = 'review'`. Milestones: words 100/300/600; stories 1/5/20. Stage precedence verbatim from spec §2.
- All prompts in `supabase/functions/_shared/prompts.ts` only, zero-dep, constraint-tested. Story levels verbatim: L1 40–80 words ≤6-word sentences present tense; L2 80–150 ≤9-word; L3 150–250.
- Every new table: RLS + explicit grants (haven pattern, as in existing migrations). Reading view shows NO Latin subtitles.
- Browser verification per task (Playwright pattern from MVP tasks; dev user mark@local.dev / vukovica-local-dev). AI happy paths: error-path live + fixture-verified structure; documented honestly (invalid local key).

### Task 1: Stage logic + progress API

**Files:** Create `lib/stages.ts`, `lib/__tests__/stages.test.ts`; Modify `lib/api.ts` (add `getProgress`).

**Interfaces:**
- Produces `computeProgress(inputs: { drillStats: DrillStatRow[]; knownWords: number; storiesRead: number }): Progress` where `Progress = { stage: 'azbuka'|'reci'|'citanje'|'razgovor'; letterMastery: { mastered: number; total: 30; weakest: string[] }; knownWords: number; knownMilestone: 100|300|600; storiesRead: number; storyMilestone: 1|5|20; nextGoal: string }`. `nextGoal` is a short Serbian+English line the dashboard renders verbatim.
- Stage rules (spec §2): azbuka until all 30 mastered; citanje primary once azbuka complete AND known ≥ 100; razgovor once known ≥ 300 AND stories ≥ 5; else reci. `weakest` = up to 5 unmastered letters sorted by accuracy asc (unattempted = 0).
- `api.getProgress(): Promise<Progress>` — one Promise.all: full drill_stats select; count user_cards state='review'; count stories finished (`stories` table may not exist yet this task — implement the query defensively: catch relation-missing error → 0, with a comment that Task 3 creates it; remove nothing later).

**Steps:** TDD `computeProgress` (stage boundaries at exactly 29/30 letters, exactly 100/300 known, 5 stories; mastery edges at attempts 7 vs 8, accuracy .899 vs .9; weakest ordering; milestone ladder rollover), implement, wire `getProgress`, full suite + typecheck, commit `feat: progression stage logic`.

### Task 2: Dashboard + trainer progression UI

**Files:** Modify `app/(app)/index.tsx`, `app/(app)/trainer.tsx`.

**Interfaces:** Consumes `api.getProgress()` via React Query key `['progress']` (invalidate alongside `['dashboard']` where reviews/drills/stories mutate — trainer round save, review submit, story finish (Task 4 wires its own)).
- Dashboard layout: stage header (stage name in Cyrillic + nextGoal), primary action button per stage (azbuka→trainer, reci→review, citanje→reader href (may 404 until Task 4 — use the ACTIVITIES pattern: keep href null until Task 4 wires it, primary button falls back to review when reader href null), razgovor→chat), then the always-on review/streak row, then remaining activities in stage order with chat LAST until razgovor stage.
- Trainer: header shows "Савладано X/30" from progress; round summary marks mastered letters; invalidates `['progress']` after stats save.

**Steps:** implement; browser-verify stage emphasis flips by seeding data states (fresh user → Азбука; SQL-seed mastered letters + 100 known → Читање emphasis with review fallback button; verify chat is last). Full suite + typecheck, commit `feat: staged dashboard + trainer mastery`.

### Task 3: Stories schema + story/gloss functions

**Files:** Create `supabase/migrations/<ts>_stories.sql`, `supabase/functions/story/index.ts`; Modify `_shared/prompts.ts`, `_shared/__tests__/prompts.test.ts`, `supabase/functions/generate/index.ts` (add `gloss` mode), `supabase/config.toml`, `lib/types.ts` (StoryRow).

**Interfaces:**
- `stories` table verbatim spec §3.1; grants + owner-only RLS.
- POST `story` `{ level: 1|2|3, topic?: string }` → inserts row for the authed user and returns `{ id, title_cyr, body_cyr, level, word_count, created_at, finished_at }`. Prompt built from `buildStoryPrompt(level, knownWordsSample, topic?)` (prompts.ts; constraint tests: Ekavian, Cyrillic-only instruction, children's register, all three level bands' numeric ranges present, known-words ~10% instruction). Server fetches the known-words sample itself (user_cards state='review' join cards, sample ≤120 words). `generateObject` zod: title_cyr, body_cyr; server computes word_count. Validates body is Cyrillic-only (reuse/port the seed-deck regex) → 502 `invalid_story` if not (never insert a bad story).
- `generate` mode `gloss`: `{ mode:'gloss', word, sentence }` → `{ base_form_cyr, en, note }` (Haiku, zod, `buildGlossPrompt` in prompts.ts). NOTE: the final review flagged mode `example` as unreachable — leave it; do not remove in this task.
- Usage logging surfaces: 'story' and existing 'generate'.

**Steps:** prompt tests first → prompts → migration (apply locally, replay check `db reset --local` + reseed + re-signup per README) → functions → curl smoke (401, CORS, 502-on-bad-key live; zod/insert path via the OpenAI-compatible mock pattern from Task 6 if quick, else fixture reasoning documented). Full suite + typecheck, commit `feat: stories schema + story/gloss functions`.
