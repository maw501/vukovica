# Vukovica Phase 3 — The Revamp (Design Spec)

**Date:** 2026-08-30
**Status:** Approved by Mark in chat (30 Aug, ~20:25) — "yes", plus grammar section + free audio additions.
**Builds on:** docs/specs/2026-08-29-vukovica-design.md (MVP), docs/specs/2026-08-30-phase2-progression-reader.md (Phase 2). Both complete on branch `mvp`, deployed to https://vukovica.vercel.app.

## 1. Purpose and direction change

Mark's restated goals: talk to his wife and son in Serbian (not an AI); read the actual
Cyrillic children's books at home — first *Guess How Much I Love You* («Погоди колико те
волим»), which he reads to his son nightly. First milestone: learn the alphabet via an
audio flashcard deck.

Direction change: **all runtime AI is removed**. Content (cards, stories, grammar drills,
book renderings, audio) is pre-generated by Claude in working sessions and seeded into the
database. The app becomes a pure flashcards + reader + drills app over Supabase. Zero
OpenAI dependency at runtime.

New capabilities: letters deck, capture queue (phrases Mark wants translated), books with
photo upload (Claude transcribes offline), grammar drills, XP/progress layer, English UI.

## 2. Removals (delete, not park)

- `app/(app)/chat.tsx`, `lib/chat.ts`, tutor references everywhere.
- Edge Functions: `tutor`, `generate`, `story`, `tts` — delete source AND undeploy from
  hosted project (`npx supabase functions delete <name>`). `_shared/` AI plumbing
  (provider.ts, prompts.ts, usage.ts) goes with them; keep nothing that has no caller.
- `lib/api.ts`: createStory (edge call), glossWord, tutor/TTS-edge calls. `lib/edge.ts`
  goes if no callers remain.
- Reader "Нова прича" (generate story) UI.
- AI-gloss fallback in the story reading view (replaced — see §6 tap behaviour).
- Client TTS-fetch path in `lib/audio.ts` (playback of stored files stays).
- Settings: any AI/provider-related copy.
- Docs: README + ship-runbook updated (functions section removed; deploy = db push +
  seed + static build; note the one-time local audio batch).
- `.env`/config: EXPO_PUBLIC_* unchanged (supabase URL/anon key only). Supabase secrets
  for AI can be unset (AI_PROVIDER, OPENAI_API_KEY, AI_CHAT_MODEL, AI_FAST_MODEL).

Chat history table (if any) can remain in the DB — no migration to drop user data.

## 3. English UI

All chrome switches to English: screen titles, buttons, stage names, goal lines, empty
states, error copy. Serbian/Cyrillic appears ONLY as learning content (card faces, letter
glyphs, story/book text, drill prompts and answers, example sentences). Stage names:
Alphabet, Words, Reading, Books. Existing Serbian UI strings ("Завршио сам", "у шпил",
"Нова прича", "Савладано X/30" etc.) are all replaced.

## 4. Letters deck

- `cards` gains `kind text not null default 'word' check (kind in ('word','letter'))`.
- 30 letter cards seeded (kind='letter'): `sr_cyr` = the letter pair as printed («Б б»),
  `sr_lat` derived pair («B b»), `en` = short mnemonic + example word, e.g.
  "b as in book — беба (baby)". Example word chosen from the seeded deck where possible.
- Review flow for a letter card: front shows the Cyrillic pair large + play-audio button;
  reveal shows Latin pair + mnemonic/example + audio replay. Same FSRS scheduling and
  `submit_review` RPC as words.
- The letters deck is SEPARATE in the queue: review screen takes a deck filter
  (`kind`); dashboard shows "Letters" as its own activity with its own due count. Word
  reviews and letter reviews never mix in one session queue.
- Trainer (typed transliteration drills) is unchanged and remains the source of letter
  MASTERY for progression (drill_stats attempts ≥ 8, accuracy ≥ 0.9).

## 5. Audio (pre-generated, free-first)

- One-time local batch script (`scripts/generate-audio.ts` or `.sh`, documented):
  generates a clip per letter card (letter name/sound + example word) and per word card
  (sr_cyr), uploads to the existing `audio` storage bucket, writes the storage path to a
  new `cards.audio_path text` column.
- TTS engine, free-first: try **Piper** (open-source local TTS; Serbian voice
  `sr_RS-serbski_institut-medium`) → quality-check by generating a sample set first;
  fallback **espeak-ng** Serbian only if Piper unavailable. If both unacceptable, leave
  `audio_path` null (app degrades: no play button) and note OpenAI TTS as the paid
  fallback for later (account currently has zero credits — free is the only path tonight).
- App playback: `lib/audio.ts` plays the storage file for `audio_path` (public or signed
  URL consistent with existing bucket policy). No runtime synthesis anywhere.

## 6. Books (the centrepiece)

- Tables:
  - `books`: id uuid pk, user_id, title_en text not null, title_cyr text, status text
    check in ('pending','ready') default 'pending', source text check in
    ('claude','photos') , created_at. Owner-only RLS + grants.
  - `book_pages`: id uuid pk, book_id fk, user_id, page_no int, text_cyr text (null while
    pending), photo_path text (storage path, null for Claude-authored), created_at.
    Owner-only RLS + grants. Unique (book_id, page_no).
- New storage bucket `book-photos` (private; owner-scoped policies like `audio`).
- In-app flow: Books list (reader tab or own tab) → "Add book" → title + photograph/upload
  pages (expo-image-picker; ordered) → book saved status 'pending'. Claude transcribes the
  photos in a working session (offline job: read photos from storage, write text_cyr per
  page, flip status to 'ready'). Pending books show "Waiting for transcription".
- Reading view: one page at a time (photo thumbnail optional/none in v1 — text is the
  content), every Cyrillic word tappable via the existing tokenizer. Tap behaviour
  (replaces AI gloss, applies to stories too): exact card match → show card (en, example,
  audio); no match → show transliteration (derived, pure function) + a one-tap
  **"Request translation"** button that files the word+sentence into the capture queue
  (§7). "Finished" button per book sets finished_at (add `finished_at` to books) and
  awards XP.
- Seed now (Claude-authored, before photos exist): «Погоди колико те волим» — Claude's
  best Serbian rendering of *Guess How Much I Love You* as a 'claude'-source ready book
  (clearly labelled "Claude's rendering — photograph your copy for the real text"), plus
  a ~40-word GHMILY vocab pack added to `cards` (hare/ears/arms/moon/love phrases...),
  plus 3–4 warm-up stories (§8) using mostly that vocab. When Mark photographs the real
  book, a second 'photos' book supersedes; the rendering stays until he deletes it.

## 7. Capture queue (requests)

- Table `requests`: id uuid pk, user_id, text_en text not null (what Mark typed, or the
  tapped word + sentence context), source text check in ('typed','reader') default
  'typed', status text check in ('pending','done') default 'pending', card_id uuid null
  (fk cards, set when fulfilled), note text null (Claude's comment), created_at, done_at.
  Owner-only RLS + grants.
- App: a quick-add screen — one text box ("What do you want to say in Serbian?"), submit,
  and a list of requests newest-first showing pending/done; done rows link to the created
  card. Reachable from the dashboard.
- Fulfilment is an offline Claude job each session: translate pending rows → insert cards
  (both scripts, example sentence) → generate audio for them (same batch script) → set
  status='done', card_id, note.

## 8. Stories

- Keep the `stories` table and reader UI; remove generation. Stories are seeded by Claude
  (INSERT migrations or seed script runs). Seed tonight: 3–4 GHMILY warm-up stories
  (level 1, mostly GHMILY vocab) + keep the 3 existing fixture stories if quality passes
  review, else replace.
- Tap-gloss in stories follows §6 tap behaviour (card match → card; else transliteration
  + request button).

## 9. Grammar section (new)

- Tables:
  - `grammar_topics`: id uuid pk, slug text unique, title_en, explain_md text (short
    English explanation with Serbian examples), sort int. Content rows are global
    (read for authenticated; no user_id) — seeded, not user-generated.
  - `grammar_items`: id uuid pk, topic_id fk, prompt text (e.g. "ја ___ (волети)" or
    "I love — ја ___"), answer_cyr text, accepted_lat text[] null (accept Latin typed
    answers via transliteration instead if simpler — decide in implementation, spec
    requirement: Mark may type either script and be marked correct), note text null,
    sort int.
  - `grammar_stats`: user_id, topic_id, attempts int, correct int, updated_at; pk
    (user_id, topic_id); owner RLS; atomic bump via RPC (pattern of bump_drill_stats).
- UI: Grammar screen — topic list with per-topic accuracy; topic view shows explain_md
  then a drill run (10 items: type the answer, check = exact match on cyr OR
  latToCyr(input) match; show correct answer + note on miss). XP per completed run.
- Seed ~12 beginner topics focused on conjugation of simple phrases (Mark's ask):
  present tense of бити/јесам, имати, волети, хтети, моћи, ићи, видети, знати, јести,
  спавати; personal pronouns; simple negation (не + verb). Each: short explanation +
  12–20 drill items. Ekavian, beginner register, family/home vocabulary.

## 10. XP + progress (clear, English)

- Table `xp_events`: id, user_id, amount int, kind text check in ('review','drill',
  'grammar','story','book_page','book_finish','request'), created_at. Owner RLS.
  Awards (server-side where a RPC exists, client insert where not): review answer 2,
  trainer round 10, grammar run 15, story finished 20, book finished 50. Level =
  1 + floor(totalXP/150). Daily goal: 30 XP/day; dashboard ring shows today's XP
  (local-day semantics identical to streak).
- Progress screen (new, English): streak + longest, XP total/level/today-ring, letters
  mastered x/30 (trainer stats), words known with 100/300/600 ladder, stories finished,
  books finished, requests fulfilled count. Dashboard header: compact version (streak,
  today's XP ring, stage + one goal line, primary action).
- Stage logic (`lib/stages.ts`) reworded to English and re-targeted: Alphabet (master 30
  letters) → Words (100 known) → Reading (finish 5 stories) → Books (finish a real
  book — the capstone goal line: "Read Погоди колико те волим to your son"). Soft as
  before; chat stage gone.

## 11. Out of scope

Speaking practice, offline mode, native builds, per-word reading analytics, OCR
automation (Claude reads the photos; no OCR pipeline), audio recording capture.

## 12. Testing & verification

- Pure logic TDD: stage rework, XP level/daily math, letter-card queue filter, tokenizer
  unchanged, transliteration answer-checking for grammar.
- Migration replay clean from scratch; RLS + grants on every new table; RPCs follow
  submit_review pattern (SECURITY INVOKER, auth.uid(), revoke PUBLIC/anon).
- Browser verification per task against local stack (dev user), as prior phases.
- Content quality: every Serbian content batch (letters, GHMILY rendering + vocab,
  stories, grammar topics) is reviewed by a separate reviewer agent for language
  correctness (Ekavian, natural register, Cyrillic-only, script round-trip) before
  seeding.
- Deploy at the end: db push, seed hosted, functions deleted from hosted, rebuild
  (English UI, ALLOW_SIGNUP=false), redeploy, live smoke.

## 13. Success criteria

1. No Edge Functions deployed or referenced; app fully functional with zero AI config.
2. UI entirely English (Serbian only as content).
3. Letters deck reviewable with audio (or gracefully silent if free TTS fails quality).
4. GHMILY rendering + vocab pack + warm-up stories + 12 grammar topics seeded and usable.
5. Capture queue: request from dashboard AND from an unknown tapped word; visible statuses.
6. Books: photo upload creates a pending book end-to-end (transcription is an offline job).
7. Progress screen + XP live; dashboard leads with streak/XP/stage in English.
8. All tests green; migrations replay; deployed to production.
